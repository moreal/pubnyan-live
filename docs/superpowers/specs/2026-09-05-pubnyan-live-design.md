# pubnyan-live: design

Date: 2026-09-05
Status: approved

## Goal

Produce animations of pubnyan, the Hackers' Pub mascot, from a single motion
definition, and export them to Lottie, Rive, animated SVG, and video. Run the
ongoing animation work as an agentic workflow on Flue, where Sonnet-class
subagents author clips and a director agent verifies and commits.

The source artwork is the `hackers-pub/visual-identity` repository, consumed as
a git submodule. It is licensed CC BY-SA 4.0 by Bak Eunji; every exported
artifact and the README must carry that attribution.

## Non-goals

- Editing the mascot's design. Only the shipped shapes are animated.
- A web player or UI component library. `dist/` holds plain files.
- Supporting the Rive editor round trip. Our `.riv` files are runtime files,
  not editor projects.

## Source artwork facts that drive the design

- Each expression export (`pubnyan-{normal,angry,curious,cry,shy}-transparent.svg`)
  contains one group of 10 real paths: 5 white, 5 black. The rest of each file
  (about 750 paths) is Illustrator clip-path debris that must be stripped.
- Groups are numbered, not named. A hand-authored mapping file assigns part
  names.
- `starorbit-*.svg` holds the ring alone, used for the loading spinner.
- Coordinates come with a `matrix(1.333,0,0,-1.333,...)` transform and
  `clip-path` per path. The rig normalizes these into plain path data in a
  single artboard space.

## Architecture

```
pubnyan-live/
  vendor/visual-identity/    git submodule
  rig/
    parts.map.json           hand-authored: source path id -> part name, pivot
    pubnyan.rig.json         generated by rig-extract; committed
  motion/                    THE single definition
    clips/*.clip.ts          one clip per file
    machine.ts               state machine
    index.ts                 exports { rig, clips, machine }
  packages/
    ir/                      types, validators, easing library, sampling
    rig-extract/             submodule SVG -> rig JSON + preview PNG
    export-svg/              animated SVG (CSS @keyframes), one file per clip
    export-lottie/           Lottie JSON per clip + one .lottie bundle
    export-rive/             .riv writer + key table generator
    export-video/            puppeteer frames -> ffmpeg (mp4, webp, gif)
    verify/                  headless render, parity diff, contact sheets
  agents/                    Flue agents, tools, skills
  docs/backlog.md            shared task queue (checkbox list)
  dist/<target>/             committed export output
```

Runtime: Node 26 (native TypeScript execution), npm workspaces, vitest. Flue
requires Node, so the whole repo stays on Node rather than mixing in Bun.

### Rig

`pubnyan.rig.json`:

```
{
  artboard: { width, height },
  parts: [
    { name: "body", z: 0, pivot: [x, y], fill: "#000000", path: "M..." },
    { name: "eye-l.white", z: 3, pivot: [...], fill: "#ffffff", path: "M..." },
    ...
  ],
  expressions: {
    normal:  { "eye-l.white": "M...", "eye-l.pupil": "M...", "mouth": "M..." },
    angry:   { ... }, curious: { ... }, cry: { ... }, shy: { ... }
  }
}
```

Part names are stable identifiers and are the only thing clips reference.
Planned names: `body`, `ear-l`, `ear-r`, `eye-l.white`, `eye-l.pupil`,
`eye-r.white`, `eye-r.pupil`, `mouth`, `nose`, `ring`, `tail`. The mapping file
decides the final list once the paths are inspected; parts that turn out to be
one path in the source (for example ears fused into the body silhouette) are
animated through their parent.

Expressions are alternate path data for a subset of parts. `rig-extract`
records, per part, whether the expression variants share a vertex count. Shape
tracks morph when counts match and crossfade when they do not.

Pivots are hand-set in `parts.map.json` (for example the base of an ear), with
the bounding-box center as the default.

### Clip DSL

```ts
export default clip("idle", { duration: 4, fps: 30, loop: true }, [
  track("body", "scale", [
    key(0,   [1, 1]),
    key(2,   [1.02, 0.98], ease.inOutSine),
    key(4,   [1, 1],       ease.inOutSine),
  ]),
  track("eye-l.white", "shape", [ key(3.0, "normal"), key(3.1, "blink"), key(3.2, "normal") ]),
  track("ring", "rotation", [ key(0, 0), key(4, 360, ease.linear) ]),
]);
```

Properties: `position` ([x, y]), `rotation` (degrees, around pivot), `scale`
([sx, sy]), `opacity` (0..1), `shape` (expression name). Easings are named
entries in `packages/ir/easing.ts`, each defined as a cubic bezier so every
exporter maps them exactly. Clips are validated at load time: known part names,
known properties, monotonic key times, values within the clip duration.

`packages/ir` also provides `sample(clip, t)`, which returns every part's
resolved transform and path at time `t`. Exporters that cannot express a
feature natively fall back to sampled keyframes, and the verifier uses
`sample` as the reference.

### State machine

```ts
export default machine({
  inputs: {
    expression: enumInput(["normal", "angry", "curious", "cry", "shy"], "normal"),
    react:      trigger(),
    loading:    bool(false),
  },
  layers: {
    idle:       { states: { idle: loop("idle") }, entry: "idle" },
    expression: { states: fromExpressions(), transitions: onInputChange("expression", { duration: 0.2 }) },
    reaction:   { states: { none: empty(), nod: oneShot("nod") }, transitions: onTrigger("react", "nod") },
  },
});
```

Mapping per target:

- Rive: native state machine with the same input names.
- dotLottie: the bundle's state machine definition with the same input names.
- SVG and video: one file per clip plus `manifest.json` listing clips and the
  machine definition, for consumers that wire their own logic.

### Exporters

Every exporter implements:

```ts
export(rig: Rig, clips: Clip[], machine: Machine, outDir: string): Promise<ExportedFile[]>
```

- `export-svg`: one SVG per clip. Each part is a `<path>` with a CSS
  `@keyframes` animation. Shape tracks use `d` interpolation where counts
  match, opacity crossfade otherwise. Also the human-readable preview target.
- `export-lottie`: one Lottie JSON per clip (shape layers, keyframed
  transforms, shape-path keyframes for morphs). A `.lottie` bundle holds all
  clips and the state machine.
- `export-rive`: writes a `.riv` (major format 7). Object and property keys are
  generated into `packages/export-rive/src/keys.generated.ts` by a script that
  parses `include/rive/generated/**/*_base.hpp` from a pinned `rive-runtime`
  checkout. Emitted objects: Backboard, Artboard, Shape, Path with cubic
  vertices, Fill with SolidColor, LinearAnimation with KeyedObject,
  KeyedProperty, and KeyFrameDouble plus cubic interpolators, StateMachine with
  inputs, layers, states, and transitions.
- `export-video`: renders Lottie output with lottie-web in puppeteer to PNG
  frames and encodes mp4, webp, and gif with ffmpeg.

### Verification

`packages/verify` is what lets an agent trust its own work.

- Structural: rig, clip, and machine validators; Lottie JSON schema check; the
  `.riv` file is loaded in `@rive-app/canvas` and its artboards, animations,
  and state machine inputs are enumerated and compared with the machine
  definition.
- Reference frames: `sample(clip, t)` rendered to PNG at fixed sample times.
- Parity: each target is rendered headless at the same sample times and
  compared to the reference with a perceptual diff. The threshold is a
  configured constant; a failure prints the worst frame's time and diff score.
- Contact sheet: one PNG per clip with sampled frames from every target side
  by side. Agents and humans review this file.

`npm run verify` runs all of it and exits non-zero on any failure. CI runs it
on every push.

### Agentic workflow (Flue)

Agents live in `agents/` as `'use agent'` TypeScript modules.

- `Director`: Opus-class model. Tools: `read_backlog`, `mark_done`,
  `run_verify`, `git_commit`. Reads `docs/backlog.md`, picks the first unchecked
  item, delegates to `Animator`, then to `Reviewer`, commits on an `agent/*`
  branch when verify passes, marks the item done. `usePersistentState` keeps
  the current item across turns so an interrupted run resumes.
- `Animator`: `useSubagent` with `model: 'anthropic/claude-sonnet-5'` and a
  `local()` sandbox with `cwd` set to the repo. Skills: `rig-reference`
  (part names, pivots, expressions), `clip-dsl` (the DSL and easings),
  `pubnyan-motion` (how this mascot should move: small amplitudes, ring is the
  "alive" element, star mouth is the focal point). Writes or edits a clip, runs
  `npm run verify`, reads the contact sheet, iterates until green.
- `Reviewer`: Sonnet, read-only sandbox. Runs the exporters and parity tests,
  reviews contact sheets, returns pass or a findings list the Director feeds
  back to `Animator`.

Running: `just agent` (or `npm run agent`) executes
`flue run agents/director.ts -m next --id pubnyan` in a loop until the backlog
is empty. A scheduled GitHub Action runs the same command. The backlog is a
markdown checkbox list so humans add and reorder work with an editor.

Boundaries: agents never edit `vendor/`, `rig/parts.map.json`, or
`packages/*` unless a backlog item says so. They commit only after
`npm run verify` passes. `AGENTS.md` at the repo root states these rules and
is loaded by Flue and by pi.

## Milestone 1 deliverables

Clips: `spinner` (ring only, loop), `idle` (breathe, blink, ring orbit, loop),
expression transitions `normal -> {angry, curious, cry, shy}` and back
(state machine driven), reactions `nod`, `tilt`, `ear-twitch`, `tail-flick`
(one-shot). Every clip exported to all four targets with parity passing.

## Phases

1. Scaffold: submodule, workspaces, TypeScript, vitest, CI, `flue init`,
   AGENTS.md, README with attribution.
2. `rig-extract` and `packages/ir`. Deliverable: `pubnyan.rig.json`,
   validators, `sample()`, a preview PNG of all five expressions.
3. `export-svg` and `packages/verify`. First clips: `spinner`, `idle`.
4. `export-lottie` with the `.lottie` bundle, parity tests green.
5. `export-rive`, spiked first: a static artboard with one rectangle that
   loads in `@rive-app/canvas`; then shapes; then animations; then the state
   machine. Parity tests green.
6. `export-video`, Flue agents, backlog seeded with expression transitions and
   reactions. From here the Sonnet agents do the animation work.

Phases 1 to 3 are done directly so the agents inherit a working verify loop.
Phases 4 to 6 are written as backlog items and can be executed by subagents.

## Risks

- Rive writer: format details not covered by the docs (interpolator objects,
  state machine transition conditions) may need reverse engineering with
  `rivinfo` from real `.riv` files. Mitigated by the incremental spike order
  and by loading every output in the real runtime.
- Flue is at 2.0.x and its API may move. Agent modules are thin; skills and
  tools are plain files that pi can also load.
- Morph quality: expression variants likely have different vertex counts.
  Crossfade is the fallback; matched-count redraws are a later backlog item.

## Testing

- Unit: validators, easing curves, `sample()`, `.riv` varuint and property
  encoding, key table generation.
- Integration: each exporter on the `spinner` clip, loaded back by the
  target's own runtime.
- Parity: every clip, every target, in CI.
